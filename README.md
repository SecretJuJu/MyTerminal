# MyTerminal

Ghostty의 터미널 코어를 macOS 네이티브 창에 임베드한 개인 작업 터미널이다. 로컬 셸은 libghostty가 PTY로 실행하고, 창·테마·워크플로 기능은 이 앱이 담당한다.

## 실행

개발 중에는 프로젝트 루트에서 실행한다.

```sh
make run
```

더블클릭할 수 있는 macOS 앱을 만들려면 다음을 실행한다.

```sh
make bundle
open MyTerminal.app
```

번들은 실행 파일과 Ghostty의 셸 인테그레이션·terminfo 리소스, 앱 아이콘을 함께 넣는다. 기본 셸은 로그인 셸이며, 창을 모두 닫으면 앱도 종료한다.

아이콘 원본은 `Support/AppIcon.svg`이고 구운 결과(`Support/AppIcon.icns`)는 저장소에 들어 있다. 원본을 고쳤을 때만 다시 굽는다.

```sh
make icon
```

## 프로젝트

왼쪽 사이드바가 프로젝트 목록이다. 프로젝트는 여러 저장소의 worktree를 한 디렉터리에 모아 둔 작업 단위이고, 터미널은 저장소가 아니라 그 디렉터리에서 열린다. claude처럼 실행한 자리에 히스토리를 남기는 도구를 쓰면 저장소별로 흩어지지 않고 프로젝트 하나에 쌓인다.

`프로젝트 추가`를 누르면 이름과 만들 위치를 묻는다. 기본 위치는 `~/MyTerminal`이다.

```
~/MyTerminal/ax-refactor/     ← 터미널이 여기서 열린다
├── .myterminal.json
├── web/                      ← ~/workspace/web 의 worktree
└── server/                   ← ~/workspace/server 의 worktree
```

`레포 추가`는 경로를 직접 치거나 `찾아보기…`로 고른다. 저장소의 하위 디렉터리를 골라도 최상위로 올라가고, 이미 넣은 저장소면 worktree 경로를 골라도 걸러낸다. worktree는 프로젝트 이름을 딴 `myterminal/<이름>` 브랜치로 만든다. 브랜치를 프로젝트마다 가르는 이유는 git이 다른 worktree가 이미 물고 있는 브랜치를 체크아웃하지 못하기 때문이고, 덕분에 같은 저장소를 여러 프로젝트에 넣을 수 있다. 원본 저장소의 작업 트리는 건드리지 않는다.

그 브랜치를 이미 다른 곳에서 쓰고 있으면 어디서 쓰는지 경로를 알려 준다. 그쪽을 옮기거나 지운 뒤 다시 시도하면 된다.

프로젝트를 고를 때마다 셸이 새로 뜨지 않는다. 처음 들어갈 때 하나 만들고 그 뒤로는 유지하므로, 오가더라도 각 셸과 스크롤백이 그대로 남는다.

## 탭과 분할

탭은 프로젝트에 속한다. `myproj`에서 ⌘T를 누르면 `myproj`의 탭이 하나 늘고, 사이드바로 다른 프로젝트에 갔다 오면 그 프로젝트의 탭이 그대로 기다린다. 탭이 하나뿐이면 탭바를 감추므로 탭을 쓰지 않으면 예전 화면과 같다.

탭 하나는 ⌘D로 좌우, ⇧⌘D로 상하로 나눌 수 있다. 새 pane은 나눈 pane이 마지막으로 있던 디렉터리에서 시작한다. ⌘W는 나뉘어 있으면 pane 하나만 닫고, 하나뿐이면 탭째 닫는다. 창을 닫는 것은 ⇧⌘W다.

| 하는 일 | 키 |
| --- | --- |
| 새 탭 / 새 창 | ⌘T / ⌘N |
| pane 닫기·탭 닫기 / 창 닫기 | ⌘W / ⇧⌘W |
| 다음 탭 / 이전 탭 | ⌃⇥ / ⌃⇧⇥ |
| n번째 탭 | ⌘1 … ⌘9 |
| 오른쪽 분할 / 아래 분할 | ⌘D / ⇧⌘D |
| pane 옮겨 가기 | ⌘⌥ + 방향키 |
| 탭을 새 창으로 빼기 | ⌃⌘N |
| 모든 창 합치기 | `Window` 메뉴 |
| 사이드바 접기 | ⌃⌘S |
| 폰트 크게 / 작게 / 되돌리기 | ⌘+ / ⌘- / ⌘0 |
| 프롬프트 사이 이동 | ⌘↑ / ⌘↓ |
| 전체 선택 / 화면 지우기 | ⌘A / ⌘K |

`Window` 메뉴의 `Merge All Windows`는 다른 창의 탭을 전부 지금 창으로 모으고 빈 창을 닫는다. 탭을 옮기거나 합쳐도 셸은 다시 뜨지 않는다 — 그 pane이 들고 있던 프로세스와 스크롤백이 그대로 따라간다.

## 껐다 켰을 때

앱을 다시 켜면 창 크기, 보던 프로젝트, 탭 목록, 분할 배치가 그대로 돌아온다. pane에 떠 있던 글자도 다시 보이고, 그 아래에서 새 셸이 시작한다.

돌던 프로세스는 살아나지 않는다. `vim`을 열어 둔 채로 껐다면 그 화면의 글자는 남지만 vim은 다시 떠야 한다. 색과 서식은 복원 대상이 아니라 평문으로만 남는다.

복원한 탭 중 보이는 탭만 셸을 띄운다. 나머지는 클릭할 때 뜬다 — 탭 스무 개를 열어 뒀다고 켜자마자 셸 스무 개가 뜨지는 않는다.

기록은 `~/Library/Application Support/dev.local.myterminal/`에 둔다. 배치는 `workspace.json`, pane별 화면은 `sessions/`다. 지워도 다음 실행이 빈 창 하나로 시작할 뿐이다.

### 제거

목록에서 마우스 오른쪽 버튼을 누르거나 `File` 메뉴에서 제거한다.

프로젝트를 제거하면 그 프로젝트의 worktree를 `git worktree remove`로 정리한다. 다 정리되면 프로젝트 디렉터리도 치우지만, 셸 히스토리처럼 앱이 만들지 않은 파일이 하나라도 남아 있으면 디렉터리는 그대로 둔다. 원본 저장소와 브랜치는 건드리지 않으므로, 같은 이름으로 프로젝트를 다시 만들고 같은 저장소를 넣으면 하던 작업이 그대로 돌아온다.

커밋하지 않은 변경이 남은 worktree는 git이 막는다. 그러면 어느 저장소가 걸렸는지 알려 주고, 그대로 두거나 프로젝트만 목록에서 뺄지 고르게 한다. 어느 쪽이든 파일을 지우지는 않는다.

`홈`은 프로젝트에 속하지 않은 기본 셸이다. 프로젝트를 하나도 만들지 않았다면 이게 전부이고, 예전과 똑같이 동작한다.

## 테마

메뉴 막대의 `Theme`에서 바꾼다.

- `기본 (시스템 자동)`: Ghostty 기본값. 라이트 모드에서는 Alabaster, 다크 모드에서는 Afterglow를 쓴다.
- `Signature — Nocturne / Daybreak`: 이 앱의 기본 시그니처 팔레트. 시스템 라이트/다크 외관에 맞춰 Daybreak 또는 Nocturne를 고른다.
- Catppuccin Mocha, TokyoNight Storm, Dracula, Gruvbox Dark, Nord, One Half Dark

사이드바도 같이 바뀐다. 배경·글자·선택 색을 터미널과 같은 값으로 칠하므로 창 전체가 한 덩어리로 보인다. 밝기를 스스로 정하는 테마를 고르면 제목 표시줄도 거기 맞추고, 시스템을 따라가는 두 테마는 창도 시스템을 따라간다.

고른 테마는 다음 실행에도 유지된다. 폰트 크기도 같이 남는다. `settings.json`이 깨져 있으면 기본값으로 열린다.

## 한글과 비라틴 문자

앱은 설치된 폰트에서 기본 모노폰트를 찾고, 한글 자모·완성형·전각 문자를 D2Coding, MonoplexKR, Sarasa, Noto Sans Mono CJK KR, NanumGothicCoding 순으로 매핑한다. CJK 획은 `font-thicken`으로 보정한다.

한글 코딩 폰트가 하나도 없으면 매핑을 걸지 않고 CoreText 폴백에 맡기며, 그 상태를 로그로 한 줄 알린다. 폴백은 Apple SD Gothic Neo인데 `가` 한 글자가 라틴 두 칸의 0.72배라 한글이 섞인 줄에서 열이 어긋난다. 그래도 아무 폰트나 매핑하지는 않는다 — Ghostty는 매핑한 글리프를 칸에 맞춰 늘리므로, 한글이 라틴 두 글자 폭이 아닌 폰트를 넣으면 한글만 부풀어 오른다(Menlo + Apple SD Gothic Neo는 1.39배).

가장 간단한 해결은 한글 코딩 폰트를 하나 깔는 것이다.

```sh
brew install --cask font-d2coding
```

아랍어, 데바나가리, 일본어, 중국어처럼 스크립트마다 글자 모양과 조합 규칙이 다른 문자는 macOS CoreText 폴백에 맡긴다. 한글용 폰트를 모든 언어에 강제하지 않아 조합·연결 문자가 깨지지 않는다.

## 확인

```sh
make test
```

worktree를 뜨는 git 동작, 프로젝트·배치·설정 저장, 탭과 분할 트리의 규칙, 화면 기록의 꼬리 자르기를 확인한다. 진짜 임시 저장소와 임시 디렉터리를 만들어 돌리므로 통과하면 실제로 되는 것이다. AppKit 화면은 테스트하지 않는다 — 직접 띄워서 본다.

`make test`가 `DEVELOPER_DIR`를 Xcode로 맞춰 준다. swift-testing이 Command Line Tools에는 없어서 그냥 `swift test`를 부르면 모듈을 못 찾는다.

## 다음 기능 후보

1. 명령과 출력을 하나로 묶는 블록. Ghostty 셸 인테그레이션이 이미 작업 디렉터리와 명령 종료 이벤트를 제공한다.
2. 자주 쓰는 명령을 찾아 실행하는 워크플로 팔레트.
3. 실패한 명령의 출력만 AI에 전달하는 오류 설명과 명령 제안.
4. 탭을 끌어서 창 사이로 옮기기. 지금은 `Window` 메뉴로만 옮긴다.
